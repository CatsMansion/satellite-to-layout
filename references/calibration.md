# 像素 → 厘米：怎么标定，以及为什么必须交叉验证

## 一句话

**图上一段像素长度 ÷ 它的真实长度 = 比例尺。整张图共用这一个比例。**

```bash
python scripts/make_layout.py scale --px 235 --meters 29.12
```

输出：

```
图上一段 235 像素  =  实际 29.12 米
  ⇒ 1 像素 = 12.39 厘米
  ⇒ 1 厘米 = 0.0807 像素
```

之后图上量到像素数 × 12.39 = 厘米。反过来：想放一个 525cm 深的车位，图上应该是 42.4 像素。

## 三个必须注意的前提

### 1. 正射 vs 斜拍

- **卫星图（正射）**：整张图一个比例，随便量。
- **无人斜拍 / 街景截图**：远处被压缩，**同一段距离在不同位置量出来不同**。
  这种图只能量画面中心附近，而且误差会比你想的大。
- **带 3D 建筑拉伸的卫星图**（很多 App 默认开着）：楼会朝画面外侧倒，屋顶位置不等于楼脚位置。
  ⛔ 要在「平面」模式下截图，或者只量地面上的东西（车位线、路面）。

### 2. 像素坐标要按原图算，不能按显示尺寸算

看图软件把图缩放到窗口大小后，你在屏幕上量的像素不是原图像素。
要么在 100% 显示下量，要么用工具读原图坐标（Python/PIL、看图软件的「信息」面板）。

这次踩过的具体形式：一张 1080×824 的图上量楼宽，先按显示尺寸 1088 宽算的比例，
差 0.7% —— 不大，但因为后面所有数字都乘这个比例，最后一排 11 个车位会错 20cm。

### 3. 一定要交叉验证

**用两个不同的参照物各算一次比例，差值 > 5% 就不要往下做。**

```
车位宽法：一排 11 个车位 = 2750cm，图上量 222 px  ⇒  12.39 cm/px
楼宽法  ：楼宽 2912cm，图上量 236 px              ⇒  12.34 cm/px
                                                     差 0.4%  ✓ 通过
```

差得多的常见原因（按出现频率）：

1. 量的是带透视的斜拍图
2. 车位数量数错了（数了车没数线）
3. 量的是屋顶边缘而不是楼脚墙体（3D 卫星图一定会这样）
4. 参照物本身记错（比如把 4.5m 的车当成 5m）

## 一个更省事的做法：数重复单元

卫星图上最好量的是**重复的东西**：一排车位、一排开间、一排树、一排窗。

```
一排 N 个重复单元的总长 = N × 单元宽
```

比量单个单元准得多，因为误差被 N 平摊了。这次那张图就是一排 15 个车位直接读出总宽。

## 标定完不要急着全图推算

先把标定结果**套回原图验证一次**：把算出来的楼宽、车道宽、车位深，
按比例换回像素，和你眼睛看到的对一下。对不上就说明标定错了。

`make_layout.py scale` 已经把这个反查表打出来了：

```
      16 cm  =      1.3 px
     160 cm  =     12.9 px
     250 cm  =     20.2 px
     525 cm  =     42.4 px
    1094 cm  =     88.3 px
```

拿尺子在你屏幕上比一下「1.3 像素」那种小值没意义，但「车位深 42 像素」很好核。
