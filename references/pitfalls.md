# 踩过的坑

按「症状 → 根因 → 怎么发现的 → 怎么修」写。改代码前先读一遍，能省几个小时。

---

## 1. ⛔ NaN 静默失败：整张图被画到画布外，一条报错都没有

**症状**：编辑器打开后画布全白/全灰，什么也没有。控制台无报错。

**根因**：某个对象的坐标字段是 `undefined`，经 `Math.min/max` 后变成 `NaN`，
`NaN` 传染到相机的 `view.oy`，所有 `(x - view.oy) * k` 都成 `NaN`，于是整张图被"画"到了画布外。

真实触发过两次，是同一个病根的两种形态：
- 路灯对象只有 `{x, h, side}`，**缺 y** → 求内容包围盒时 `y = NaN`
- 草丛用 `o.x`（草丛只有 `x0/x1`）→ `Math.min(undefined, x1) = NaN` → 该草丛**永远选不中**

**怎么发现**：第一次是肉眼看到画布空白 + 逐行打印 `view` 对象，发现 `oy: NaN`。

**修法**（三层，缺一不可）：
1. 读文件时统一 `normalize()`：缺字段补兜底值，`Number.isFinite` 不过就重置
2. 算包围盒时显式跳过非数值
3. 服务端 `validate()` 拒绝写 `x/y` 非数字的文件

**通用教训**：`Math.min(undefined, anything)` 返回 `NaN` 而不是报错。
**凡是把外部数据喂进 `Math.*` 的地方，都要先判类型。**

## 2. ⛔ 后画的东西会把先画的标签压住

**症状**：地块名字只剩几个字露在车缝里，看着像「字被吃了」。

**根因**：地块标签和地块填充在同一个循环里画，之后才画车位/树/杆。
标签是最需要读的东西，却排在最底层。

**修法**：把标签收集起来，**在 `draw()` 的最末尾**统一画（`drawBandLabels`）。

⚠️ 挪函数时注意作用域：`W`（画布宽）是 `draw()` 的局部变量，
抽出去的函数必须**显式传参**，否则 `ReferenceError: W is not defined` —— 这个我当时就撞了。

## 3. ⛔ 同高度地块重叠 = 共面 = 整片闪

**症状**：渲染出来某块地面一片闪烁噪点，换个角度就变样。

**根因**：两个盒子的顶面在同一个 z 上，GPU 分不清谁在前面（z-fighting）。

真实触发过两次：
- **街角路口**：两条车行道都铺过路口 → 交叉那块方地两个面同高
- **转角路缘**：侧街路缘铺到 `road_y0`，而主街路缘从 `road_y0 - 16` 开始 →
  转角处重叠一个 16×16cm 的小方块 → 那个角闪

**判据**：`check_layout.py` 的「同类型地块重叠」检查。
**16×16cm 这么大点的重叠，眼睛在平面图上根本看不出来** —— 必须用坐标算。

**修法**：路口那块方地**只让一条路独占**；转角的人行道/路缘**止于另一条路的路缘上边线**。

## 4. ⛔ 路口断开 / 人行道横铺到车道上

**症状**：两条街在平面上看是 T 形，但路口那块是空的（或反过来，人行道横着铺到了车道上）。

**根因**：修 #3 时最容易修过头 —— 为了不重叠，把所有地块都在路口前收住，结果路口漏空。

**正确做法**：
```
车行道：都延长到路口外边线（互相"相邻"，边贴边，不重叠）
人行道/路缘：在路口前收住（止于另一条路的路缘上边线）
```
判断标准：**车行道的边要能接上，人行道的边要能断开**。

**判据**：`check_layout.py` 的「人行道压在车行道上」+「车行道没接上」。

## 5. ⛔ 车停在人行道上

**症状**：平面图上看不出问题；一渲街景就假 —— 车浮在人行道砖上。

**根因**：车的 `y` 用了 `curb.y1 + 40` 这类"看着差不多"的推导，
而路缘上边线往上才是人行道。差 40cm 就整个压上去了。

**判据**：`check_layout.py` 算车的实际占位矩形与人行道矩形的重叠面积，> 4 m² 报警。

**修法**：平行停车用 `curb.y1 + 40`（贴路缘停），垂直车位用 `楼前沿 + 20`（车头朝楼）。

## 6. ⛔ 改了布局，渲染没变 —— 因为漏了一步烘焙

**症状**：改完 `layout.json` 重渲，出来的图跟上一版一模一样，逐像素都一样。

**根因**：渲染管线是两段式的：
```
layout.json  →  [烘]  →  scene.json  →  [渲]  →  png
```
只跑了第二段。几何是从 `scene.json` 读的，`layout.json` 的改动根本没进去。

**怎么发现的**：盒子总数没变（`EnvLayer 636 faces` vs 应该的 `858 faces`）。
**⭐ 判据就是这个：改完布局，下游的图元数量必须变；没变就是没吃到。**

**修法**：把「烘」和「渲」串成一条命令，或者在渲之前打印一行
`[LAYOUT] 读到 N 条地块 / M 台车`，让"没读到"可见。

## 7. ⛔ 尺寸判据把合法的窄条当成坏数据丢掉

**症状**：路缘石整条消失，路面直接接人行道。

**根因**：`band_list()` 里写了 `if x1-x0 < 20: skip`，想挡"退化成一个面"的坏矩形。
但**竖向路缘石的宽度只有 16cm** —— 合法数据被这条判据杀了。

**修法**：判据改成 `< 1.0`（只挡真正退化成一个面的），并且**丢掉时打一行日志**。

**通用教训**：任何"过滤坏数据"的阈值，都要先想一遍**合法数据的最小尺寸**是多少。
窄条、薄片、路缘、线脚 —— 这些天然就小。

## 8. ⛔ 两个并行的初始化抢同一个全局状态

**症状**：下拉框显示的文件名，和实际载入的文件不是同一个。

**根因**：页面上有两个各自 `fetch("/api/list")` 的 async IIFE：
一个负责渲染文件下拉，一个负责决定"读哪个文件"。
它们都改 `CURRENT_FILE`，**谁先跑完谁赢**。不是逻辑错，是竞态。

**修法**：合成**一条**启动链 —— 取列表 → 决定文件 → 渲染下拉 → 载入。
注释里明确写「别再加并行的 IIFE」。

**通用教训**：多个 async 初始化函数共享状态时，**要么串成一条链，要么显式 await 同一个 Promise**。

## 9. ⛔ 校验脚本自己漏了一层，于是误报

**症状**：`check_layout.py` 说 4 棵树"不站在任何地块上"，但那几棵树明明长在后院草地上。

**根因**：地面有两种来源 —— `bands`（地块）和 `grass`（草丛区块）。
判据只把 `bands` 和楼体算进"地面"，忘了 `grass`。

**修法**：`all_rects` 同时收 `bands` + `grass` + `building`。

**通用教训**：**校验脚本也要有阳性/阴性对照。**
这次的完整对照是：
| 样本 | 期望 | 实测 |
|---|---|---|
| 正常布局 | 通过 | ✅ 通过 |
| 两条路重叠 | ERROR | ✅ ERROR |
| 车压人行道 | ERROR | ✅ ERROR |
| 车在楼里 | ERROR | ✅ ERROR |
| 树在荒郊 | WARN | ✅ WARN |

只跑"正常样本通过"是不够的 —— 那只能证明脚本不误报，证明不了它抓得到错。

## 10. ⭐ 平面图的 +Y 向下 = 镜像俯视，和街景渲染左右相反

**症状**：平面图里横街在**右**边，站到街上拍出来横街在**左**边。用户第一反应是"你做反了"。

**根因**（不是 bug，是坐标约定）：
- 平面图：`屏幕y = 世界y`，即 +y 向下 → 这是**真实俯视图的左右镜像**
- 街景：从街道一侧看向建筑，视线朝 -y，右手方向 = 世界 -x
  → +x（横街那一侧）出现在画面**左**边

两者必然相反，因为一个是镜像俯视、一个是正视。

**这次的处理**：不动几何。平面图跟卫星照片一致（横街在右），街景渲染自然相反。
**在交付时明确说一句**，比偷偷翻转渲染图好。

**要改的话**：平面图改成 +y 向上，它就变成真俯视，和街景一致。
代价是所有 `W2S/S2W`、拖拽、缩放锚点都要跟着翻，不是一行改动。

## 11. ⭐ 相机左右方向靠几何硬推会推错，要打标记实测

**症状**：按 `to_track_quat('-Z','Y')` 的数学关系推算"画面右 = +x"，
渲出来发现是反的，白等一轮渲染。

**根因**：手推叉乘时符号很容易错一处，而**错了不会有任何提示**，只是图镜像。

**可靠判据**：给场景里一个**只在某一侧**的东西涂一个刺眼的颜色（洋红 `(255,0,255)`），
渲一张 50% 小图，看它在画面哪一侧。30 秒定论。

这次就是给东端（x ≥ 2952）的台阶涂洋红，一渲就看到它在画面左边 ⇒ 画面右 = -x。

**通用教训**：涉及左右/镜像/手性的判断，**不要靠推算，要靠标记实测**。
